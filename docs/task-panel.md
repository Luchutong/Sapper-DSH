# Sapper 比赛工作台

适用版本：0.1.0-alpha.19，仅支持 DSH NEXT 0.2.1-rc.2。

## 开始使用

1. 点击桌面左侧 **Sapper 比赛工作台**，无需先打开工作区或会话。输入框附近和插件设置页的按钮也跳转到这里。
2. 点击 **新建题目**，首次使用 **选择文件夹** 指定比赛根目录；之后会记住。只需填写任务目标，题名可选。提交前可检查或调整有效模型、Agent preset 和权限，默认沿用最近明确选择；不会自动提升权限。
3. 有附件时在 **题目附件 → 添加附件** 中多选 ZIP、程序、图片或其他文件，可在创建前移除。点击 **创建并开始** 后，先建立题目目录、DSH 原生工作区与主会话，再显示上传进度；全部附件保存到本题 `attachments/` 后才登记目标并启动任务，随后打开主会话。无附件按原流程启动，输入框可继续编辑。
4. 默认两题同时执行，其余 FIFO 排队；工作台右上角可调为 1–8。降低并行数不取消已运行题目；排队期间没有子代理或模型请求。DSH 自身的子代理容量限制仍生效。
5. 成功工具输出出现常见格式的 flag 后，主会话立即显示 **未验证 flag · 可先提交测试**，无需等子会话清理或复核。默认随后停止本轮；非标准格式也可通过带真实回执的结构化 flag 候选即时回传。正常元数据写入不重复确认，执行工具仍服从所选权限。

创建请求有持久化 requestId。失败不会删除已经创建的目录、文件、工作区或会话；点击 **继续创建** 或列表中的 **创建未完成** 复用同一请求。重复点击和断线重试不会再建一份。要更换失败请求的目标或目录，点击 **另建题目**。题目目录含时间和随机后缀，同名、中文、Windows 保留名称均有处理。

**选择文件夹** 支持 DSH 的两种目录后端：native 打开系统选择器，browse 在表单内显示目录层级与子目录，进入目标文件夹后点 **使用此目录**。可直接输入宿主机的绝对路径并打开、返回主目录或显示隐藏目录；截断的目录列表会明确提示。手动填入比赛根目录也可直接创建，无需先打开选择器。

## 题目附件

附件通过 DSH 原生二进制通道上传，不经插件 JSON RPC 搬运文件内容。每题最多 128 个文件，插件不额外限制单文件字节数；传输与保存使用流式接口。原始文件名保存在清单中，落盘路径加顺序前缀并清理不合法字符，例如 `attachments/01-题目.zip`，中文、同名与 Windows 路径均可使用。上传完成记录大小与 SHA256，不自动解压或执行；分析工具仍服从本题权限。

上传中可 **取消上传**；退出页面也会取消当前传输。已创建的目录、会话和已保存文件会保留，尚未收齐附件时不会启动模型。在原表单点击 **继续创建** 会跳过已保存文件；关闭页面或重启后，从列表点击 **创建未完成，点击恢复**，按提示重新选择尚未上传的同名、同大小原文件。宿主已经接收但复制失败的文件会从持久化存储继续，无需重新上传。此功能按文件恢复，不提供文件内部的断点续传。

任务主会话卡片可展开附件清单，详情的 **文件** 标签也列出附件路径与大小；完整上传清单及 SHA256 保存在事实图的 **用户上传的题目附件** note 文档中。收到附件仅证明文件已保存，内容与结论仍须代理实际读取。无附件的新建、已有工作区命令入口和已运行任务保持兼容。

## 多 flag 与快速复核

在新建题目的 **完成与复核策略** 中选择，或在 **设置 → Sapper → 默认完成与复核策略** 设置默认值。新默认复核方式为 **轻量证据检查**；默认 flag 策略仍为 **首个即停**，多 flag 环境应选 **持续收集多个 flag** 或 **收集指定数量**。

| 完成策略 | 行为 |
| --- | --- |
| 首个 flag 即停 | 保留原比赛流程：发现后立即回显并结束本轮 |
| 收集指定数量 | 当前阶段按不同、大小写敏感的候选值累计；达到 N 个后收尾，不等待全部独立复核 |
| 持续收集 | 发现一个后继续其他路线；遇手动停止、预算/时限、无新路线等正常边界时结束 |

每个新值都会立即回传，重复输出不重复计数/通知，已知拒绝的值不计入目标。收集到 N 个表示得到 N 个候选，不代表比赛平台已接受，也不自动标为 confirmed。当前阶段多次运行累计计数；新建关联纠错/后续阶段重新取证，历史仍在题目分组中保留。WP 阶段引用历史 flag 不触发新发现或收集早停。

| 自动复核 | 行为 |
| --- | --- |
| 轻量证据检查（默认） | 复用探索者成功回执；重要的 flag/vuln/cred/loot 可补一次短检查。检查证据完整性，不启动第二个代理 |
| 关闭自动复核 | 完成取证后记录观察，不额外安排复核调用；仍要求真实成功回执，flag 字面值须实际出现在引用输出中 |
| 仅所选重要结论独立复核 | 对设置中的类型启动原独立 verifier，其余使用轻量记录 |
| 所有结论独立复核 | 保留原 explore → verify 路径 |

轻量检查不足时，保留“已有工具证据、未独立复核”的观察并继续，不暗中启动完整 verifier，也不丢失结果。重要类型的两次检查必须来自两个真实工具调用，重复引用同一回执不算；flag 检查比较原始输出中的字面值。轻量检查不等于语义正确性证明。完整 `confirmed` 状态仍只由不同子会话的独立复核产生。

普通快速结果会保存为可召回的观察 note，原意图标为已完成取证，调度器不自动重做；完整候选与轻量检查记录在运行文件中。事后仍可点 **独立复核**，强制走原 verifier，无论当前默认模式是否关闭。快速策略的“本轮完成”与“目标已独立复核完成”分别展示。

已经因首个 flag 停下的阶段，打开 **概览 → 调整完成/复核策略并继续**，选择“持续收集”及所需复核模式后点击 **按此策略继续**。活动阶段会沿用原图与已有发现；已完成阶段新建关联后续阶段，原运行不覆盖。也可使用 `/sapper collect all` 或 `/sapper collect 3`，命令快速受理，输入框不等待后台运行。查看/编辑草稿不会发起任务；只有明确点击继续才执行。

新建请求将策略写入原启动清单，重试和重启恢复不更换策略。已有阶段可在详情显式覆盖，默认设置修改不重写历史运行；修改插件配置仍会停止当前运行，请在任务开始前设置。详细契约见 [alpha.19 验证](alpha19-validation.md)。

alpha.13 若出现 `cannot get property "commands" without inject` 或重启后恢复失败，升级 alpha.14 并重启 DSH，点击原题目的 **创建未完成，点击恢复 → 继续创建**。原目录、工作区和主会话会复用，无需另建题目或删除记录。恢复表单显示原请求配置及已保存的错误；本次修复详见 [alpha.14 验收](alpha14-validation.md)。

## MCP 工具与推理强度

升级后完全退出并重启 DSH，进入 **设置 → Sapper → 工具与模型能力**。选择 **检查主会话**，再点 **刷新能力**，查看该工作区/preset 的注册工具、描述和父会话可见状态。未选择会话时显示全局范围，可能不含项目或 preset 专属工具；页面不会执行 MCP 业务调用，也不把注册成功显示为网关健康。

探索和独立复核分别配置工具范围。可使用 **全部 MCP**，或取消全选后按公开名称前缀（如 `mcp__ida__*`）和精确工具（如 `mcp__ida__decompile`）选择，分别点击 **保存探索工具范围 / 保存复核工具范围**。搜索同时匹配名称和描述；未连接/未匹配的旧配置保留在展开区，可移除或补充。非 MCP 工具只支持精确名称，`*`、`read*`、图写入和递归委派不能作为外部取证工具放行。只打开页面不会写入设置。

新默认值包含 `mcp__*`，允许子代理使用父会话可见的 MCP 工具；已有显式 `exploreTools` / `verifyTools` 数组不会被升级覆盖。设置页保存会写回对应数组，后续工具注册按前缀匹配；宿主和父会话拒绝仍优先。规划 reason 保持只读图查询，MCP 只进入 explore/verify 的取证链，证据仍须由不同子会话实际调用。

MCP 服务、凭据与连接范围继续通过 DSH 官方 MCP 或 MCP 连接器管理。新题目使用独立目录：原工作区专属连接不自动变成全局连接。连接器的“按会话启用”按 Agent 隔离，主会话已激活也不保证新子会话可见；需遵循连接器的激活流程，或由用户选择适合比赛的“始终注入”模式。Sapper 不复制凭据、不替用户激活连接、不覆盖连接器治理。修改网关或插件安装后应完整重启宿主，刷新网页不能替代后端重载。

**模型与默认推理强度** 使用当前 DSH 模型适配器声明的档位。可设置全局默认，并展开规划/探索/独立复核分别选择角色模型与档位；优先级为角色显式档位 → Sapper 默认 → 父会话/模型默认。更换角色模型而未指定档位时，由 SDK 清除旧模型专属的继承档位；显式指定不支持的档位会在子代理模型请求前报错，不会静默降级。新建题目的“模型”展开区另有 **任务推理强度**，用于设置主会话及其默认继承值。

工具范围、角色模型、推理强度与原编排配置一样，保存会停止当前运行，请先配置再启动。完整契约和验证边界见 [alpha.18 记录](alpha18-validation.md)。

## 查看与干预

左栏按题目聚合求解、独立复核和 WP，提供目标搜索与运行中/排队/已结束筛选。右侧固定标题和状态，分为：

- **概览**：目标、候选/已复核 flag、单个候选的独立复核、方向输入和执行操作。
- **执行记录**：阶段、历史运行、路线结果与活动；预算、子会话和原始错误折叠显示。
- **证据**：探索和独立复核使用的不同子会话、工具回执与摘要。
- **事实图**：按依赖分层；适应视口、缩放、拖动、重置、键盘选择节点与完整标题；明确显示未纳入视图的节点数。
- **文件**：打开本题 WP.md 与 evidence/ 中的文本文件。新生成 WP 同时归档在该阶段 `artifacts/rNNN/WP.md`，历史查看优先呈现当次字节快照，列表明确区分快照与当前文件；单个归档上限 4 MiB，失败不会删除原文件。预览最多 64,000 字符，只呈现文本，不执行 HTML 或脚本。

候选结果按类型显示：`note` 等普通分析为“候选结果 · 尚未复核”，`vuln` 为“漏洞候选 · 尚未复核”，仅 `flag` 显示“未验证 flag · 可先提交测试”。普通分析通过独立复核也不等于已获取 flag。详见 [alpha.16 复盘](alpha16-validation.md)。

点击题目、切换阶段或执行记录、打开文件均不启动模型，不切换宿主当前执行图，不回传重复结果。执行接口按 `workspaceId + taskId + runId` 定位，同为 r001 的不同阶段不会混用。

运行中点击 **停止任务** 或填写 **调整探索方向**。停止会等待真实工具体和子代理清理；方向调整保留证据，清理后建立关联阶段。结束后可：

- **独立复核**：只验证选定运行的某个候选，不启动其他 ready 路线。
- **继续当前阶段**：显式继续该阶段可恢复工作；已完成阶段不会被重复求解。
- **编写 WP**：建立关联的 writeup 阶段，写入并独立读取 WP.md；历史生成记录保留生成时的 flag 验证状态。
- 填写纠错要求后 **按要求重新运行**：建立关联 solve 阶段，重查错误 flag 或探索新方向，原阶段和证据保留。

已有工作区仍可用 `/sapper start <目标>`、`/sapper run`、`/sapper job`、`/sapper cancel`、`/sapper steer <方向>`、`/sapper wp [要求]`、`/sapper retry [要求]` 与 `/sapper continue <目标>`。普通对话可通过 sapper_control 干预，重复启动会被后台管理器拒绝。原 sapper_task / sapper_dispatch 兼容入口仍等待执行结果；日常启动优先使用工作台或快速受理命令。

## 主会话结果

受理、进展和核心 flag 即时显示为可见卡片，长 WP/证据在详情和文件中查看。任务保存最终结果后调用 **Agent.followup()** 唤醒主助手，生成一次真实文本简报；主会话忙碌时延后，不中断用户。真实用户消息优先处理。

flag 发现通知与任务结束简报分开。发现时就可复制候选并自行向比赛平台提交，插件不联网代提交，也不把“工具中出现”当作“答案已确认”。默认停止探索后，由用户选择是否 **独立复核**；若项目已配置继续复核，后台运行和阶段卡片不会隐藏这个候选，只有复核成功或失败才更新其可信状态。WP 引用历史 flag 不重复报新发现。详见 [alpha.15 验收](alpha15-validation.md)。

自动简报轮次由宿主禁用所有工具并限制为一次模型请求，避免自动重启编排。约束只属于该轮，不影响后续普通用户对话，也不会误拦截用户明确提交的后台任务。简报按执行 job ID 持久化去重，刷新、阶段更新、打开历史不会重复生成。失败保留卡片和证据，可在概览点击 **重试简报**。手动 `/sapper result` 仍可按需补发卡片，不触发第二次自动简报。

## 持久化与恢复

题目事实图仍为 Python 兼容的 `.sapper/tasks/t-UUID/`，`.sapper/tasks/index.json` 记录阶段及关联关系；旧 `.sapper/project.json` 作为 legacy 保留。

宿主独立 storageDomain `sapper_workbench` 保存根目录、并行数、模型/preset/权限偏好、创建步骤、队列、结果和简报去重。UI 和队列偏好不属于编排 Config，调整它们不会使正在运行的配置指纹失效。页面切换不卸载后台管理器；客户端根服务持有相关会话引用。重启恢复排队项，执行中项目显示 **已中断**，须显式继续/恢复；完成任务和旧简报不重放。

RPC 只向 DSH 本机 owner 开放。查询只能定位已登记工作区及其图；文件预览受目录边界、符号链接和白名单约束。创建目录由用户显式选择的比赛根目录限定；图和外部工具继续执行原有权限、归属、证据与完整性约束。

## 历史版本经验

以下保留各版本的问题与修复过程；旧窗口和设置页内任务面板已由上述工作台替代。

## alpha.9 首次命令启动阻塞的经验

真实 `test1` 记录显示旧命令在后台子代理已产生 confirmed 事实时，仍未写入 `command/done`。两次命令分别等待约 58 秒、161 秒才返回。DSH 新会话输入器在命令提交期间处于 `submitting`，因此保持只读，表现为欢迎页无反应。

alpha.10 将命令改为共享后台管理器的快速受理操作，任务使用独立取消信号，通过原 ToolRuntime 执行；请求返回或会话输入器释放不取消任务。模型/文件权限检查保留，异步失败由 job/面板展示。命令取消会等待实际工具体和子会话清理完成后才标为终止。

补充回归使用同版本 DSH 浏览器产物中实际的 SubmitMachine，与真实 CommandRuntime、ToolRuntime 和阻塞的子代理联动，检查命令已结算且输入器回到 `plain` 时任务仍运行，并验证可查询、拒绝重复提交、取消及只读失败后重试。此前只验证工具和独立面板，漏掉了新会话命令提交的输入器生命周期。

## alpha.11：结果回传、预算与连接修复

每轮后台任务结束后，主会话自动出现展开的 **Sapper 任务结果** 卡片，区分已独立复核的事实、未确认候选及复核失败；停止原因可直接查看。结果作为 `sapper/result` 会话事件持久化，重新打开会话仍可展示，不需要主模型再次运行。模型下一轮也会收到带不可信数据声明的结果摘要。`/sapper result` 或窗口内 **发送结果到主会话** 可补发当前任务的最近运行，包括旧版本失败运行中的候选。

例如原 test2 有候选但复核在第 12 步后耗尽预算，升级不会手工提升该候选为 confirmed。可先补发结果，再用 **继续当前任务** 或 `/sapper run`：若仍有复核次数且候选未被拒绝，会直接启动新复核子会话，不重复探索；证据门与跨调用复核次数约束保持生效。

设置页 **复杂任务预算** 默认自动模式：explore/verify 的初始 24 步在取得新的成功外部工具输出时按初始步数延长，最多 128 步；重复相同调用与输出不会获得延期，reason 不因图查询延期。临近预算结束预留最多两步，停止新增外部调用并要求提交已有证据支持的结构化结果。仍有子会话 45 分钟、整轮 90 分钟与每请求 16384 输出 token 上限，均可在设置页修改。固定模式严格使用初始步数。旧显式值保留；配置修改会使当前运行停止，因此请在启动前修改。

设置页 `cannot get property "remote.sapperPanel" without inject` 来自 Cordis 的命名空间依赖检查：仅注入 `remote` 不会获得 `remote.sapperPanel`。现先挂载贡献，再通过动态 `ctx.inject(['remote.sapperPanel'], scoped => ...)` 使用该作用域的 remote。新增真实插件 fiber 回归，既复现旧作用域拒绝，也验证修复后的会话列表、状态和操作。

浏览器探针同时检查最终构建客户端的设置页会话选择、受裁切输入容器中的可见按钮、视口顶层窗口、事实图、结果卡片、手动补发与 Esc 关闭/焦点恢复。截图为 `dist/validation/panel-dialog.png` 与 `panel-results.png`。另用同版 SDK 实际历史组装器及 Chat builder 检查实时结果与重新加载，不将独立组件测试当作整个桌面应用验收。真实 test2 数据只读诊断，未自动重跑其外部目标。

## alpha.12：发现 flag 即结束、主会话干预与后续阶段

求解阶段首次收到带本次成功工具回执的 `kind=flag` 结构化候选后，编排器先保存候选，立即停止其他流水线并回传主会话，回收子会话后本轮以 `completed / flag-found` 结束。不再启动自动 verify 或新 reason，也不自动执行清理、扩大枚举或外部提交。尚未复核的候选会明确标注，不能等同 confirmed；如需验证，可显式调用 `sapper_dispatch mode=verify`（指定旧 run_id 与 intent_id）。已经存在的 confirmed flag 也会令求解 run 直接结束，拒绝/纠错状态不会被当作新发现。

普通任务仍沿用 explore → verify。该 flag 约束由调度器执行，prompt 仅补充要求探索者观察到 flag 后立即提交。框架的发现时点是通过回执检查的结构化候选，不是任意工具文本里出现类似 flag 的示例字符串。已发出的外部命令只能请求取消并等待平台回收，不能撤销已发生的操作。

从窗口、slash 命令或主会话控制工具发起后台任务时，会立即追加可见的受理卡片，随后更新规划、探索、复核等阶段；结束后更新为结果。活动记录保留在卡片中，重新打开会话仍可查看。阶段通知不会强行唤醒主模型。

| 主会话命令 | 行为 |
| --- | --- |
| `/sapper steer 检查另一条入口` | 运行中接受新方向，停止/回收旧路线后自动启动关联新阶段；只允许任务发起会话发出 steer |
| `/sapper cancel` | 停止当前任务，并撤销尚未启动的方向调整 |
| `/sapper wp 补充复现过程` | 结束后依赖保存的证据编写本地 `WP.md`；默认不重新访问外部目标 |
| `/sapper retry 原 flag 被拒绝，重新检查` | 结束后启动新的求解/纠错阶段；无参数时使用前序目标 |
| `/sapper continue 重新独立核查结论` | 用明确目标启动后续阶段 |
| `/sapper result` | 补发当前任务最近结果；即使运行被取消，也展示已保存的结果 |

普通聊天可调用 `sapper_control`：action=steer / continue / cancel / status / result，goal 为用户提供的方向或后续目标；continue 的 purpose=writeup 用于本地 WP，purpose=solve 用于重新求解/纠错。写入操作仍受 DSH 会话权限控制，子代理无此工具权限，不新增模型可控的绕过参数。

窗口也提供 **补充方向或后续要求** 输入框；运行时点击 **按新方向继续**，结束时点击 **编写 WP** 或 **重新运行 / 纠正 flag**。新阶段自动创建关联任务图，目录索引与 project 中记录 parent_task/purpose，原 completed 图及事实不重写。历史结果以 note 进入新阶段，附带原图路径、候选、复现步骤和证据；不会复制成新的 confirmed。WP 阶段关闭遇 flag 即停，避免引用报告中的历史 flag 导致提前结束。更正后的 flag 需要新的取证，旧记录继续保留以供追溯。

本地回归覆盖并发路线停止、及时候选通知、无自动复核/无额外 reason、所有子会话退出、意图释放、主会话调整方向、取消排队方向、只读拒绝、completed 后 WP 与纠错。WP 用例实际写出文件并由另一子会话读取；这些确定性模型测试验证流程，不代替在线模型的 WP 内容质量验收。
