# alpha.17：创建题目时上传附件

仅支持 **DSH NEXT `0.2.1-rc.2`**，不声明兼容其他 DSH 版本。

## 使用

左侧 **Sapper 比赛工作台 → 新建题目 → 题目附件 → 添加附件**，可一次选择多个 ZIP、二进制、图片或其他文件。创建前可移除文件；创建后显示每个文件的字节进度和保存状态。所有附件落盘后，才启动题目并打开主会话。

文件原样存入本题 `attachments/`，文件名带顺序前缀以保留同名附件，Windows 不合法名称会安全转换。插件不自动解压或执行文件，不提升所选会话权限。详情 **文件** 标签和主会话卡片可查看路径、大小，事实图中 **用户上传的题目附件** note 的 doc 保存完整清单及上传时 SHA256。代理实际读取后才能形成内容结论。

每题最多 128 个附件；没有额外的单文件字节上限，使用 DSH 流式上传/存储接口，不将文件整体编码成 JSON。大文件仍需等待实际传输、持久化和摘要校验。

取消、断线或退出页面不会启动附件不齐的任务，已保存文件会保留。点击原创建记录的 **继续创建**，跳过已保存文件，只重新选择未完成上传的同名同大小原文件；单个未完成文件从头传输。宿主已接收的文件引用持久化后，即使复制失败并重启，也可从 DSH 存储继续，不需要重新上传或新建题目。

## 验证范围

- 保留 alpha.16 的 186 项测试，新增 6 项附件回归，覆盖实际二进制字节与 SHA256、中文同名文件、重复导入、附件未齐禁止启动、附件 note 和主会话/详情元数据。
- 使用真实 SDK FileUploads 和 LocalAttachmentStore，覆盖精确 Session 凭证归属、已有不同内容文件不覆盖，以及复制故障后 Domain/JSONL 冷重启恢复同一个目录、工作区和会话。
- 实际 Workbench 渲染覆盖多选/移除、第二个文件失败仅重试该文件、取消不启动任务、恢复时只重新选择缺失文件，以及上传 Session 引用在打开主会话后释放。
- 最终客户端浏览器探针使用真实 SDK FileUploadRuntime、Blob Worker、二进制 HTTP handler 和本地 AttachmentStore，上传 ZIP/bin 后逐字节读取题目目录比对；继续覆盖真实 DSH 插槽、Gateway、工作区和会话接口、输入框可编辑、只读历史、WP 及浅色/深色 × 1024/1280/1440 布局。

浏览器测试适配了连接/身份边界和客户端 Cordis 注册，模型为确定性适配器；Windows 隔离安装用于验证正式兼容门禁与安装产物，不等于在完整桌面手工完成附件上传。用户原始题目、日志和 test4 记录未改动。

本地 `pnpm check` 的 192/192 项测试通过，类型检查、双端构建和官方兼容门禁通过，无版本豁免。最终打包构建的宿主回归与浏览器探针 69/69 项通过。Windows 临时 DSH_HOME / 隔离 profile 安装退出码 0，安装后的宿主和客户端摘要与本地产物一致，未修改日常桌面 profile。
