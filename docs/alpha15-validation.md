# alpha.15：flag 即时回显，不等待独立复核

运行时保持 DSH `0.2.1-rc.2`，包含 alpha.14 的目录选择与创建恢复修复。

## 现场证据与原因

本次只读检查用户新题目的运行和子会话日志：探索会话的成功 `tool/result` 已包含 `CTF2{…}`，随后 `structured_output` 也声明了 `kind=flag`，主会话却尚未出现该值。已启动的 verifier 实际在复核另一条普通接口探测，不能据此确认或延迟这个 flag。

旧调度器在整个 explore 激活完成并清理后才解析候选并回传。因此，即使结构化候选已提交，子会话的清理仍可能延迟通知；同批次其他路线又可能已经进入独立复核。候选可见性不应依赖这些流程结束。

## 当前行为

- 在成功外部工具输出中发现常见 `flag{…}`、`CTF2{…}`、`*CTF{…}`、`HTB{…}` 等格式时，立即保存带本子会话回执的 flag 观察并写入主会话结果卡片，标为 **未验证 flag · 可先提交测试**。不扫描模型推理、用户目标或图摘要来产生新发现。
- 非标准格式由有真实工具回执的 `kind=flag` 结构化输出触发同一通知，不等待激活清理完成。
- 默认 `stop_on_flag` 行为保留：通知后终止其他探索并保留候选，后续显式“独立复核”可继续。若项目已配置 `stop_on_flag=false`，也会先通知，再允许原复核继续；复核不是通知的前置条件。
- 新增运行级 `flag_observations`，普通进度/复核卡片替换显示时仍保留未验证值。相同候选在同一运行只触发一次发现通知；同值的正式 flag 验证成功后更新为已复核，普通 note 的验证不能将其标为已确认。
- 不创建未经过独立复核的 confirmed 事实，不代替用户向比赛平台提交。未复核的 flag 可以先由用户提交测试；失败后仍可纠错重跑。
- writeup 阶段不把外部工具回显的历史 flag 当作新发现，也不改变历史 WP 的验证状态。

工具结果观察接口是同步通知，异步保存与回传由编排器单独持有并排队；进入下一验证阶段前会等待这些通知，但通知本身不等待子会话退出或其他验证。权限、配置变化和取消检查继续执行。

1. 刻意阻塞 explore 的 dispose：标准格式和非标准格式两种 flag 均已在主会话可见，任务仍为 running、尚无最终结果且没有 verifier；解阻后候选仍可显式复核。
2. 刻意阻塞可选 verifier：主会话已显示未验证 flag；后续 verify 进度保留该值，事实仍未 confirmed；解阻后才更新为已独立复核。
3. 模型仅在文字/结构化输出中伪造 flag，没有成功外部回执时，不产生发现通知。
4. 原 WP 回归补入工具回显的历史 flag，确认不触发新的 flag-found。
